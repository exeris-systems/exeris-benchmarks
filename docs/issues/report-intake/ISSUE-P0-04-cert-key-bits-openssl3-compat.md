# ISSUE P0-04: cert_key_bits OpenSSL 3.x Compat Fix

Status: verified (pass)
Priority: P0
Primary Agent: Implementer
Secondary Handoff: None

## Scope

In-scope:
- Fix `cert_key_bits()` regex in `tools/bench/lib/certs.sh` to correctly parse RSA key size output from both OpenSSL 1.x and OpenSSL 3.x.

Out-of-scope:
- Changing function signatures in `certs.sh`.
- Modifying benchmark logic, scenario semantics, or threshold values.
- Fixing EC or ed25519 key-size detection unless they share the same root cause.

## Root Cause

`cert_key_bits()` uses a bash regex `\(([0-9]+)\ bit\)` that requires a literal `)` immediately after `bit`. This fails on OpenSSL 3.x (and OpenSSL 1.x for RSA), which outputs:

```
Private-Key: (2048 bit, 2 primes)
```

The trailing `, 2 primes)` prevents the regex from matching, so the function returns `0`. The caller `assert_cert_key_type_and_size` then emits:

```
ERROR: Unable to determine key size for /tmp/exeris-bench-certs/smoke-key.pem (got '0')
```

OpenSSL 1.x RSA output is also affected: `RSA Private-Key: (2048 bit, 2 primes)` — same format.

## Fix Applied

File: `tools/bench/lib/certs.sh`, function `cert_key_bits()`.

**Before:**
```bash
if [[ "$line" =~ \(([0-9]+)\ bit\) ]]; then
```

**After:**
```bash
if [[ "$line" =~ \(([0-9]+)\ bit ]]; then
```

The closing `\)` is removed. The regex now matches `(N bit` regardless of what follows, covering:
- `(2048 bit)` — OpenSSL 1.x without primes suffix
- `(2048 bit, 2 primes)` — OpenSSL 1.x and 3.x RSA
- `(256 bit)` — EC keys

## cert_key_type() Analysis

`cert_key_type()` was inspected and requires no fix. It uses string matching on lowercased output:
- OpenSSL 3.x RSA without `-traditional`: `private-key: (2048 bit, 2 primes)` — matched by `"2 primes"` fallback.
- OpenSSL 3.x RSA with `-traditional`: `rsa private-key: ...` — matched by `"rsa private-key"`.
- OpenSSL 3.x EC: `asn1 oid:` line present — matched by `"asn1 oid"`.
- ed25519 / ed448: direct string match, unaffected by format changes.

## Risks and Caveats

- **Low risk**: The looser regex `\(([0-9]+)\ bit` could theoretically match unexpected lines, but `awk 'NR==1 || /Private-Key:/ {print; exit}'` constrains input to the first relevant line only.
- **Caveat**: EC and ed25519 key-size detection was not verified against live OpenSSL 3.x EC output. If `cert_key_bits` is ever used with EC keys, further testing is recommended. EC key size appears in the curve name, not a bit-count line, so `cert_key_bits` may return `0` for EC regardless — acceptable for current usage.
